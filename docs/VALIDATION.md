# v0.7 검증 결과

v0.6과 같은 개발 자료를 사용해 메뉴와 숫자 영역 재인식, 할인 행 해석을 비교했습니다. 원본 OCR·정답·이전 APK·모델 해시를 보존했으며, 원본 OCR 74건은 변하지 않았습니다. 개별 거래 정보가 포함된 사진과 원시 기록은 로컬에 보존합니다.

## 실행 조건

- 입력: 스캔 63건과 기존 사진 11건. 두 묶음에 중복 가능성이 있어 독립된 영수증 74장으로 해석하지 않습니다.
- 실행: Android 11(API 30), x86_64 에뮬레이터, CPU 2개·메모리 2GB·480×960 화면
- 동일 최종 APK로 네트워크를 끈 상태에서 검증. 실제 ARM 휴대폰 성능은 미측정입니다.
- 통과: Android 테스트 82개(63건·11건 배치 포함), JVM 19개, Python 평가 테스트 9개
- 배치 처리 오류와 이름·숫자 재인식 진단 오류: 0건

검증 APK SHA256:

```text
13f29de381117c1336cca2c2eef036770e9ffda08d8cf12f25aefd257e5bc04b
```

이는 당시 빌드 식별값입니다. 로컬 디버그 서명 등 빌드 환경이 다르면 새 APK 해시는 달라집니다.

## 개선 결과

| 항목 | v0.6 → v0.7 |
|---|---|
| 누락 수량 | 25개 → 0개, 복원한 25개 모두 원본 대조 일치 |
| 메뉴 이름 | 4종·5개 행 개선, 변경 입력 검토에서 새 문자 오독 없음 |
| 인쇄 합계 | 74건 모두 유지 |
| 추출 계산 합계 | 69건 유지, 제거·쿠폰 해석 관련 5건 수정 |
| 63건 처리 시간 중앙값 | 7.504초 → 10.643초 |
| 63건 총 처리 시간 | 479.620초 → 755.032초 |
| v0.7 최대 처리 시간 | 24.676초 |

수량 복원 25개 중 23개는 실제 숫자 영역 재인식, 2개는 수량 열의 `개` 접미사 처리로 해결했습니다. 메뉴는 다른 영역 보정본과 모델 출력이 뒷받침하는 경우에만 보수적으로 채택하며, 후보를 직접 선택할 수도 있습니다. 추가 인식으로 처리 시간은 늘었습니다.

## 필드별 표본 비교

아래 묶음은 서로 겹칩니다. 이름은 NFC 정규화 후 공백·문장부호를 제외해 비교합니다. 인쇄되지 않은 단가는 정답 단가로 평가하지 않으며, 합계 일치만으로 메뉴·수량이 정확하다고 판정하지 않습니다.

| 평가 묶음 | 이름 정답 행 | 수량 정답 행 | 행 금액 정답 행 |

일부 복합 메뉴명·브랜드명·영문 단위·쿠폰 이름의 오독은 남아 있습니다. 반복해서 개선에 사용한 자료이므로 위 수치는 새로운 영수증에 대한 일반화 정확도가 아닙니다. 최종 금액과 품목은 원본을 확인해야 합니다.

## 재현 범위

빌드와 사진 없는 JVM·Python 테스트는 [README](../README.md)의 명령으로 실행합니다. 실제 사진을 요구하는 `PaddleScanTest`, `BatchTest` 및 평가 스크립트는 기존 원본·정답·이전 결과가 필요합니다. `PaddleScanTest`는 특정 원본의 예상 금액까지 검사하므로 임의 사진으로 대체할 수 없습니다.

PC에서 실행한 대형 OCR 모델 실험은 앱에 탑재한 엔진이나 휴대폰 실측 결과에 포함하지 않았습니다. 현재 앱의 Notion 전송·촬영·영구 저장 기능도 검증 범위에 포함되지 않습니다.
